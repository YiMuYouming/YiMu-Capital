# 弈沐资本数据看板 v2.5 升级改造计划

> 日期：2026-05-25
> 来源：全面评估报告 + 平台升级计划（融合版）
> 执行顺序：P0 → P3 → P1 → P4 → 顶栏 KPI

---

## 一、结论

当前项目已经具备个人交易系统的核心骨架，但还差四个关键能力：

1. **运行底座稳定** — 不能依赖碰运气
2. **规则统一口径** — widget 和 AI 不能各讲各的
3. **盘前可验证** — 一眼判断今天数据能不能信
4. **交易可复盘** — 能归因、能看决策质量

---

## 二、现状

### 做对的部分

- `bridge.py + store.js + widget` 完整数据闭环
- SSOT 审计通过（8 大数据域唯一来源）
- W03/W14/W15/W22 等核心交易视图
- `LLM_RULES.md` 把规则显式化，AI 不是黑盒
- 三层 PnL 保护机制
- CSS 变量系统（54 个变量）
- `YiMuWidget` 基类生命周期清晰
- DataStore 三层合并架构正确

### 主要问题（来自评估报告）

**架构层**
- Python 运行环境不完整，部分脚本导入会失败
- 采集路径存在硬编码，机器迁移后容易断
- `gen_dashboard_data.py` 是单点依赖，无 schema 校验
- CACHE 字段没有标准化文档（iwencai 小数 vs 百分数不一致）

**组件层**
- W05/W06 不走 DataStore，破坏 SSOT 架构
- W12/W13 代码重复（~100 行完全相同）
- W11/W12/W13/W16 事件监听器泄漏
- W14 缺少 `updateTimestamp()`
- W08/W09 `profitFx.indexOf('好')` 会错误匹配"不好"

**AI 层**
- LLM 输出格式依赖标记词，无 schema 校验
- ReAct 验证过宽松（冰点期 BUY 信号也被标记 verified）
- 手动/自动模式共享同一个流
- 交易规则分散在 LLM_RULES.md、widget 逻辑、AI prompt 中

**产品层**
- 22 个组件造成信息过载，缺少精简模式
- 缺少「信号 → 操作」的确认流程（断链 3 秒）
- W03 仓位上限不响应熔断
- 没有止损主动提醒
- 健康状态没有成为前端第一信息

---

## 三、升级目标

| # | 目标 | 说明 |
|---|------|------|
| 01 | 可信 | 盘前能快速判断数据是否新鲜、行情是否覆盖、PnL 是否正常 |
| 02 | 统一 | 规则引擎、组件提示、AI 研判、风控判断共用同一套口径 |
| 03 | 高效 | 精简模式 + 顶栏固定 KPI，减少盯盘认知负担 |
| 04 | 可复盘 | 每笔交易能回到当时的规则判断和快照，看决策质量而非只看盈亏 |

#### 涉及文件

`scripts/bridge.py` · `scripts/collectors/quotes.py` · `scripts/collectors/market_data.py` · `scripts/collectors/iwencai_poll.py` · `scripts/snapshot_auction.py` · `scripts/style_detect.py` · `README.md` · `scripts/check_runtime.py`（新建）

### P3：统一规则引擎

**目标：** 禁买、熔断、连亏、高潮、周五限制等规则只有一套口径。AI 不会直接输出未经规则验证的 BUY 结论。

> 这是整个升级计划最关键的一步。做完 P3 后，很多组件逻辑会自动简化，界面上的"重点"自然清晰。

#### 任务

- 新增 `scripts/rule_engine.py`：把交易规则结构化，提供统一查询接口
- 让 W03、W08、W09、W14、W15、W20 都读取同一份规则结果
- AI 输出引用规则引擎的结果，而不是自己自由解释硬规则
- 保留 `LLM_RULES.md` 作为人类说明文本，不再承担机器执行逻辑
- 把评估报告里的 AI 问题一并修复：
  - LLM 输出改用 JSON schema 校验（替代 `[TEXT]`/`[SIGNALS]` 字符串分割）
  - ReAct 验证增加情绪-信号联动校验（冰点不 BUY，双冰不追涨，高潮不追连板）

#### 涉及文件

`scripts/rule_engine.py`（新建） · `scripts/bridge.py` · `widgets/w1-check.js` · `widgets/w2-check.js` · `widgets/position-calc.js` · `widgets/risk-panel.js` · `widgets/llm-monitor.js` · `widgets/llm-chat.js` · `LLM_RULES.md`

#### 验收

- 禁买、熔断、连亏、高潮、周五限制等规则只有一套口径
- AI 不会直接输出未经规则验证的 BUY 结论
- 冰点期 BUY 信号不会被标记 verified
- LLM 输出能通过 schema 校验，格式漂移不静默失败

### P1：盘前健康中心 + 精简模式

**目标：** 盘前一目了然系统能不能开工。精简模式下只盯核心组件，减少认知负担。

#### 任务

**A. 健康中心**
- 新增统一健康 API `/api/health`
- 把 bridge、基线、行情覆盖、PnL、持仓一致性、竞价、AI 状态做成统一检查项
- 新增健康总览组件，放到第一屏或顶栏入口
- 让 `ymwm_report.json` 成为可视化入口

**B. 组件层修复**（来自评估报告）
- W14 增加 `updateTimestamp()`
- W08/W09 修复 `profitFx.indexOf('好')` bug（改为精确枚举判断）
- W05、W06 纳入 DataStore 订阅体系（修复 SSOT 破坏）
- W12/W13 抽象出 `StockPoolWidget` 基类（消除代码重复）
- W11/W12/W13/W16 事件监听器全部通过 `_domListeners` 追踪
- W21 梯队面板拆分为「盘中快速查看」（表格）和「盘后复盘」（完整面板）

**C. 交易断链修复**
- W08/W09 增加「录入操作」快捷入口，直接调起 W15 买入表单并预填标的
- W03 仓位上限响应熔断：当 `risk.熔断触发` 变化时重新渲染
- W14 增加止损主动提醒：计算持仓触及止损线并报警

**D. 精简模式**
- 增加「精简模式」开关，切换后只显示核心组件（W04/W07/W08/W09/W15/W22）
- 其余组件默认折叠

**E. 数据质量**
- iwencai CACHE 增加 `_fetch_time` 字段
- 前端组件据此显示「数据已过时 N 分钟」警告
- `snapshot_auction.py` 增加 10:00 备份快照

**F. 盘前预案**
- 在 W16 增加「今日预案」文本区，记录开盘前核心判断

#### 涉及文件

`scripts/bridge.py` · `scripts/snapshot_auction.py` · `scripts/collectors/iwencai_poll.py` · `index.html` · `widgets/health-center.js`（新建） · `widgets/sentiment-dash.js` · `widgets/auction-5d.js` · `widgets/risk-panel.js` · `widgets/w1-check.js` · `widgets/w2-check.js` · `widgets/position-calc.js` · `widgets/lianban-pool.js` · `widgets/trend-pool.js` · `widgets/zt-echelon.js` · `widgets/positions.js` · `data/ymwm_report.json` · `store.js`

#### 验收

- `curl http://localhost:8088/api/health` 返回各检查项状态
- 盘前一键判断平台是否可信，fail/warn 显式显示
- 精简模式下只显示 6 个核心组件
- W08 显示买入信号后，一键录入 W15 操作表单
- W14 持仓触及止损线时主动报警

**目标：** 每笔交易能回到当时的规则判断和快照，盘后看决策质量而非只看盈亏。

#### 任务

- 新增 `widgets/trade-review.js`（复盘视图）
- 盘后（15:05）自动拉取收盘数据，计算每个操作的「买在 X、收在 Y、盈亏 Z」
- 按月/季度统计最常见的错误类型

#### 涉及文件

`scripts/db.py` · `scripts/bridge.py` · `widgets/today-ops.js` · `widgets/positions.js` · `widgets/trade-review.js`（新建）

#### 验收

- 每笔交易记录带上当时快照和规则结果
- 可以统计最近交易里最常见的错误类型
- 盘后复盘视图显示「决策质量」而非只看收益曲线

### 启动检查

| 检查项 | 命令 | 预期结果 |
|--------|------|----------|
| 运行时检查 | `python3 scripts/check_runtime.py` | 明确显示正常项和失败项 |
| 桥接启动 | `python3 scripts/bridge.py 8088` | 无报错，正常监听端口 |
| 健康 API | `curl http://localhost:8088/api/health` | 返回各检查项状态 |

### API 检查

| 端点 | 预期结果 |
|------|----------|
| `/api/baseline` | 返回 dashboard_data.json |
| `/api/live/quotes` | 返回 PyTDX 行情数据 |
| `/api/pnl/summary` | 返回账户资产和盈亏摘要 |
| `/api/debug/snapshot` | 返回 8 域完整快照 |

### 规则检查

| 规则类型 | 验证条件 | 预期行为 |
|----------|----------|----------|
| 熔断归零 | 单日亏损 ≥ 3% | 总仓位上限归零，W03 显示熔断状态 |
| 连亏空仓 | 连亏天数 ≥ 2 | 强制空仓，不再开新仓 |
| 周五趋势上限 | 周五 + 趋势风格 | 趋势仓位上限 15% |
| 高潮保护 | 情绪 ≥ 85% | 连板仓位减半或清零 |
| W1 禁买 | 情绪 < 60% 或涨停收益 ≤ 2% | W08 显示"等待"信号 |
| W2 禁买 | 情绪 < 20% 或炸板率 > 40% | W09 显示"降级"信号 |
