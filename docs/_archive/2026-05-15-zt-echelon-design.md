# 涨停梯队 (ZT Echelon) — 设计文档

> W21 | 2026-05-15 | 状态: 待实施

## 概述

利用同花顺 `ths_hot` 数据源（零鉴权），构建实时涨停梯队组件。按 日期→概念→股票 三层下钻展示当日涨停全景。

## 数据源

- **实时**: `ths_hot.fetch_hot_with_zt_count()` — 同日强势股+涨停统计+题材归因
- **历史**: 同一 API 指定 date 参数拉近 5 个交易日数据
- **判定规则**: 主板(非688/300)≥9.8%=涨停，科创板(688)/创业板(300)≥19.5%=涨停
  
## 数据流

```
ths_hot API × 近5天
      ↓
consumer/dashboard.py (hot_list 扩展)
      ↓
poll_live.py (切到 consumer.build_live 调用)
      ↓
dashboard_live.json
  ├── hot_list.reason_stats → 概念词频
  ├── hot_list.zt_stocks[] → 当日涨停股全量
  └── hot_list.zt_history["2026-05-11"][] → 历史涨停股
      ↓
DataStore merge() → W21 订阅 hot_list
      ↓
zt-echelon.js 前端:
  - 连板性质: 对比 history 跨日匹配
  - 概念过滤: reason_stats Top 5 标火
  - 排序: 前端纯计算
```

## 连板性质判定

前端 JS 逐日匹配：今日涨停股 code → 查昨日 zt_stocks → 查前天 → ... 输出：
- 连续 N 天涨停 → "N连板"
- 非连续但有多次 → "N天M板"
- 仅今天 → "首板"

## LLM 槽位

- 读取 `data/llm_insights.json`（复用 W10 模式）
- 匹配关键词 "涨停梯队" / "连板" / "涨停"
- 无匹配显示全局最新研判
- 颜色 `--special-bg` 底

## 空数据

- 开盘前/无涨停数据 → 显示 "⏳ 等待开盘" 占位
- 非交易日 → 显示最近交易日缓存，标注 "昨日数据"

## 边界情况

- 历史数据不足（新股）：只显示能计算的连板深度
- API 异常：保留上次成功数据，状态栏显示 "数据延迟"
- 换手率/成交额为 null：显示 "-"

## 刷新策略

- **当日 zt_stocks**: 10-15s 轮询（ths_hot 盘中更新）
- **历史 zt_history**: 会话启动时拉一次 + 手动刷新触发，不参与定时轮询
- **手动刷新**: 当日+历史全量拉取

## 不包含

- 涨停时间（API 无此字段，后续找数据源补）
- 独立 bridge 端点（走 DataStore 现有管线）
