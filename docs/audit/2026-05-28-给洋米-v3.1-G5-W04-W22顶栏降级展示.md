## 行为要求

### 1. W04 市场全景

要求：

- fallback breadth 只有 `up/down` 时，只显示涨跌家数和粗略来源，不渲染一排 0 档分布。
- 完整分布存在时，才渲染 10 档红绿柱。
- 成交额对比只显示简单百分比：
  - `昨日 +12.3%`
  - `昨日 -8.4%`
  - 缺值显示 `昨日 —`
- 不再显示容易误读的绝对差额，例如 `-1.29 万亿`。
- 涨跌停缺数据时显示 `—/—`，不能显示误导性的 `0/6`。
- 昨日收盘基线三张指数卡片始终保留；缺值显示 `—`，不能整块消失。

### 2. W22 收益曲线

要求：

- 总资产、总盈亏仍使用账户 SSOT，只要 `valuation_complete=true` 就正常显示。
- 单只持仓 `_day_start_price=null` 时：
  - 今日分项收益显示 `基线缺失` 或 `—`
  - 不显示 `0`
  - 不影响总资产展示
- 清仓标的 `realized_today_pnl=null` 时：
  - 显示 `今日收益基线缺失`
  - 不显示 `0`
- W22 的 KPI value 和 sub 文案必须同步，不允许 value 不可信但 sub 还显示旧值。

### 3. 顶栏健康

要求：

- 顶栏健康文案最多 4 个字：
  - `正常`
  - `降级`
  - `阻断`
  - `无响应`
- 如果 `/api/health.critical_ok=true` 但有 `degraded_reasons`，显示 `降级`，不显示 `不健康`。
- 如果 `trade_entry_allowed=false`，显示 `阻断`。
- 鼠标 hover title 可包含更长原因，但顶栏文本必须短。
- 不新增一堆长文本挤压顶栏。

### 4. 数据源说明

`store.js` 的数据源说明应更新成云端实际口径：

- live index / breadth：`Eastmoney/Tencent fallback + bridge CACHE`
- PyTDX 相关字段标记为“本地/可选/云端降级”，不要写成云端必需。
- W12/W13：交易日 D 使用上一交易日复盘笔记。
