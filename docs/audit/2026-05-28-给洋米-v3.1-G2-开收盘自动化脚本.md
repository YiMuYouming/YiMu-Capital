## 设计要求

### 1. `open_day.py`

用途：开盘前本地生成今日基线，并可选择同步上云。

建议接口：

```bash
python3 scripts/ops/open_day.py --dry-run
python3 scripts/ops/open_day.py --apply
python3 scripts/ops/open_day.py --apply --restart-cloud
```

默认行为必须是 `--dry-run` 或必须要求显式 `--apply` 才允许写云端。

`--dry-run` 应该：

- 不运行会写真实数据的命令，或只打印将执行的命令。
- 打印本地项目路径、目标云端路径。
- 检查 `scripts/gen_dashboard_data.py` 是否存在。
- 如果 `data/dashboard_data.json` 存在，读取并打印：
  - `meta.generated_at` 或 `meta.updated`
  - `meta.note`
  - `meta.pools_note`
  - `meta.pools_note_date`
  - `lianban_pool` 数量
  - `trend_pool` 数量
- 打印将同步的文件：`data/dashboard_data.json`、`data/pools.json`。

`--apply` 应该：

- 运行 `python3 scripts/gen_dashboard_data.py`。
- 生成后再次读取基线摘要。
- 用 `rsync -avz --backup` 同步 `dashboard_data.json` 和 `pools.json` 到云端。
- 如果传入 `--restart-cloud`，才允许执行 `sudo systemctl restart yimu-live-dashboard.service`。
- 做只读验收：
  - `/api/baseline`
  - `/api/account/state`
  - `/api/pnl/summary`

### 2. `close_day.py`

用途：收盘后从云端生成 SQLite 一致性备份，并拉回本地。

建议接口：

```bash
python3 scripts/ops/close_day.py --dry-run
python3 scripts/ops/close_day.py --apply
```

默认行为必须是 `--dry-run` 或必须要求显式 `--apply` 才允许覆盖本地 `data/pnl.db`。

`--dry-run` 应该：

- 不创建云端备份，不覆盖本地文件。
- 打印将执行的 SSH/rsync 步骤。
- 打印将同步的辅助 JSON：
  - `dashboard_data.json`
  - `pnl_history.json`
  - `sentiment_auto.json`
  - `auction_snapshot.json`
  - `ymwm_report.json`
  - `zt_history.json`

`--apply` 应该：

- 在云端用 SQLite backup API 生成 `data/pnl.db.backup-close-YYYYMMDD-HHMMSS`。
- 在云端对备份执行 `PRAGMA integrity_check`，必须为 `ok`。
- 用 `rsync -avz --backup` 把该备份拉回本地 `data/pnl.db`。
- 同步辅助 JSON。
- 本地对 `data/pnl.db` 执行 `PRAGMA integrity_check`，必须为 `ok`。

### 3. 代码结构

为了测试简单，可以把共同函数放在一个新模块：

```text
scripts/ops/common.py
```

建议函数：

- `run(cmd, *, dry_run=False, check=True)`
- `read_baseline_summary(path)`
- `sqlite_integrity(path)`
- `build_ssh_command(remote, script)`
- `require_apply(args)`

测试中必须 mock `subprocess.run`，不要真的 ssh/rsync。
