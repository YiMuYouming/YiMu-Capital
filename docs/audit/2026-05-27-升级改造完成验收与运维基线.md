## 三、当前权威数据链

### 3.1 账户与 PnL

```text
account_baselines（日初锚点）
  + trade_records（成交事实）
  + fund_events（资金事件）
  + live quotes（实时估值）
  -> /api/account/state
  -> /api/pnl/summary
  -> W15 / W22 / 顶栏
```

规则：

- `dashboard_data.json` 可提供每日基线和展示数据，不可覆盖盘中账户事实。
- `/api/sync` 只接收成交命令，不接受客户端覆盖现金、持仓市值或总资产。
- 盘中价格变化只能改变估值和 PnL，不得改变现金和成交数量。
- 缺行情、过期行情或不可信锚点必须降级，不得生成可信资产结论。

### 3.2 实时规则与 AI

```text
account_state + sentiment/freshness + baseline style
  -> scripts/rule_engine.py
  -> rule_state
  -> widgets + LLM verification
```

规则：

- BUY 信号必须同时满足 `rule_state` 窗口许可和标的技术条件，才可视为通过校验。
- `DAY_STOP`、`DATA_UNTRUSTED`、`SENTIMENT_STALE` 等阻断不得被前端或 AI 绕过。
- LLM 输出采用结构化 JSON 协议；降级解析结果不得静默变为可信信号。

### 3.3 复盘

- W23 通过 `/api/trades/review` 读取逐笔复盘数据。
- `review_note` 和盘后 `outcome` 可追加，不修改原成交事实或资产计算。
- 手工补录/客户端声明的成交时点不能证明当时规则快照，必须保持未验证标记。

### 5.2 收盘态行情修复终验

2026-05-27 收盘后发现：行情最后快照仍存在，但系统将超过 300 秒未刷新的同日收盘行情误判为不可用，导致 W15 显示“行情不可用”、W22 KPI 显示“估值不可信”。

最终修复口径：

- 盘中行情仍按严格 freshness 校验。
- 15:00 后，同日 15:00 之后行情标记为 `quote_status=close_snapshot`。
- `valuation_complete=true` 可与 `quote_status=close_snapshot` 同时成立。
- W15/W22 在 `close_snapshot` 下显示资产、价格、仓位、PnL 和曲线，并标注“收盘快照/非实时”。
- 真正缺报价、零覆盖或跨日旧行情仍 fail-closed。
- `/api/health` 不再因可估值的收盘快照将整体标记为 `unhealthy`；盘后可为 `degraded`。

真实接口终验：
