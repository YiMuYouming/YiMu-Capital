目
升级目标
目标 01
可信
盘前能快速判断数据是否新鲜、行情是否覆盖、PnL 是否正常。健康 API + 健康中心组件让系统状态一目了然。
目标 02
统一
规则引擎、组件提示、AI 研判、风控判断共用同一套口径。禁买、熔断、连亏、高潮等只有一套解释，不再各讲各的。
目标 03
高效
精简模式只盯核心组件，顶栏固定 KPI。减少盯盘认知负担，22 个组件按需使用而非全开。
目标 04
可复盘
每笔交易能回到当时的规则判断和快照。盘后看决策质量而非只看盈亏，统计最常见的错误类型。

现状判断
做对的部分
  • bridge.py + store.js + widget 完整数据闭环
  • SSOT 审计通过（8 大数据域唯一来源）
  • W03/W14/W15/W22 等核心交易视图
  • LLM_RULES.md 把规则显式化，AI 不是黑盒
  • 三层 PnL 保护机制 + CSS 变量系统

主要问题
  • Python 运行环境不完整，部分脚本导入会失败

  • gen_dashboard_data.py 无 schema 校验，静默失败风险高
  • W05/W06 不走 DataStore，破坏 SSOT 架构
  • W12/W13 代码重复（~100 行完全相同）
  • W11/W12/W13/W16 事件监听器泄漏

  • ReAct 验证过宽松（冰点期 BUY 信号也被标记 verified）

P3
P3：统一规则引擎
第二步 · 核心枢纽
P3
统一规则引擎
核心枢纽
目标：禁买、熔断、连亏、高潮、周五限制等规则只有一套口径。AI 不会直接输出未经规则验证的 BUY 结论。

为什么是第二步：P3 是整个升级计划最关键的一步。做完 P3 后，很多组件逻辑会自动简化，界面上的"重点"自然清晰——不需要人工编排三套布局。
主要任务
  • 新增 scripts/rule_engine.py：把交易规则结构化，提供统一查询接口
  • 让 W03、W08、W09、W14、W15、W20 都读取同一份规则结果
  • AI 输出引用规则引擎的结果，不再自由解释硬规则
  • 保留 LLM_RULES.md 作为人类说明文本，不再承担机器执行逻辑
  • LLM 输出改用 JSON schema 校验，替代 [TEXT]/[SIGNALS] 字符串分割
  • ReAct 验证增加情绪-信号联动校验：冰点不 BUY，双冰不追涨，高潮不追连板
涉及文件
scripts/rule_engine.py scripts/bridge.py widgets/w1-check.js widgets/w2-check.js widgets/position-calc.js widgets/risk-panel.js widgets/llm-monitor.js widgets/llm-chat.js LLM_RULES.md
验收标准 禁买、熔断、连亏、高潮、周五限制等规则只有一套口径。AI 不会直接输出未经规则验证的 BUY 结论。冰点期 BUY 信号不会被标记 verified。LLM 输出能通过 schema 校验，格式漂移不静默失败。

  • iwencai CACHE 增加 _fetch_time 字段，前端组件显示「数据已过时 N 分钟」警告
