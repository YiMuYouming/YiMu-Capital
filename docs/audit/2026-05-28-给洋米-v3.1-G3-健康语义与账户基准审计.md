## 行为要求

### 1. `/api/health.status` 重新定义

健康总状态必须遵守：

- 有 critical issue 时：`status="unhealthy"`。
- 无 critical issue，但有非关键降级时：`status="degraded"`。
- 无 critical issue 且无降级时：`status="healthy"`。

`llm_config.status=missing` 不是交易生产 critical：

- 不应让 `critical_ok=false`。
- 不应让 `trade_entry_allowed=false`。
- 不应单独让 `status="unhealthy"`。
- 应进入 `degraded_reasons`，例如 `llm_config: missing`。

`iwencai.status=stale/delayed` 不是交易生产 critical：

- 不关闭交易入口。
- 进入 `degraded_reasons`。

`quotes.status=dead/missing` 是 critical：

- `critical_ok=false`
- `trade_entry_allowed=false`
- `status="unhealthy"`

`account.status=error/incomplete` 是 critical。

`pnl.status=error/incomplete` 是 critical。

### 2. `/api/account/audit` 增强

在不破坏现有字段的前提下新增字段：

```json
{
  "basis_status": "ok|degraded|missing_anchor",
  "overnight_positions": [
    {"code": "002049", "name": "紫光国微", "has_day_start_price": false, "day_start_price": null}
  ],
  "day_start_prices_covered": 0,
  "day_start_prices_total": 1,
  "day_start_prices_missing": [
    {"code": "002049", "name": "紫光国微"}
  ],
  "closed_positions_today_missing_realized": [
    {"code": "002436", "name": "兴森科技", "closed_date": "2026-05-28"}
  ]
}
```

保留已有字段：

- `anchor_date`
- `anchor_source`
- `anchor_effective_at`
- `overnight_positions_count`
- `overnight_codes`
- `day_start_prices_coverage`
- `day_start_prices_missing_codes`
- `closed_positions_today_count`
- `closed_positions_today`

### 3. `/api/health` 集成 account basis audit

`_build_health()` 应包含：

```json
"account_basis": {
  "status": "ok|degraded|missing_anchor",
  "coverage": "0/1",
  "missing_codes": ["002049"],
  "closed_missing_realized_codes": ["002436"]
}
```

规则：

- `account_basis.status="missing_anchor"` 时是 critical。
- `account_basis.status="degraded"` 时不是 critical，但进入 `degraded_reasons`。
- 缺 `day_start_price` 只影响今日分项收益，不应伪装成总资产不可用。
