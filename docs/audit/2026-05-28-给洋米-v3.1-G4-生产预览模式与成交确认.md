## 目标

让主人一眼知道当前打开的是生产看板还是本地预览，并且每笔成交录入后有清楚的写入结果反馈。

本任务只做小范围前端和本地预览代理增强，不做大 UI 重构。

---

## 当前背景

当前入口：

- `http://localhost:8088`：云端生产，经 SSH tunnel 到 hermes。
- `http://localhost:18088`：本地预览，加载本地代码，GET 数据读云端，写请求被代理拦截。

当前问题：

- 顶栏只显示连接状态，不明确告诉主人“云端生产 / 本地预览只读”。
- 18088 拦截写请求时，后端返回 JSON，但 W15 只显示笼统“网络错误，成交未保存”。
- W15 成交成功后只有 toast，不显示成交 ID、当前账户状态或确认来源。
- 成交失败后表单会保留，但错误原因不够具体。

## 行为要求

### 1. 顶栏模式标识

顶栏新增一个短标签，位置靠近品牌或连接状态。

建议文案：

- 8088：`云端生产`
- 18088：`本地预览 · 只读`
- file：`本地文件`
- 其他端口：`本地服务`

识别方式可先用前端 `location`：

```js
function _detectRuntimeMode() {
  if (location.protocol === 'file:') return { key: 'file', label: '本地文件', readonly: true };
  if (location.port === '18088') return { key: 'preview', label: '本地预览 · 只读', readonly: true };
  if (location.port === '8088') return { key: 'prod', label: '云端生产', readonly: false };
  return { key: 'local', label: '本地服务', readonly: false };
}
```

要求：

- 标签颜色不能和健康红绿混淆。
- 18088 标签必须明显写“只读”。
- 文字要短，不挤压顶栏。
- 不依赖云端 API 才能显示。

### 2. 18088 写入拦截要显示明确原因

`scripts/ops/local_dev_proxy.py` 已经返回：

```json
{
  "error": "readonly_dev_preview",
  "message": "本地开发预览页禁止写入；实盘录入请使用 http://localhost:8088"
}
```

W15 的 `_bridgeSync()` 必须在 HTTP 非 2xx 时尽量读取 JSON，并把 `message` 或 `error` 展示出来，而不是统一显示“网络错误”。

要求：

- HTTP 403 + `readonly_dev_preview` 时，toast 或表单错误显示“本地预览只读，请用 8088 实盘录入”。
- 表单保留，按钮恢复可点。
- `event_id` 保留，避免主人切回 8088 后重试时重复生成。

### 3. 成交成功确认

成交成功后应显示更明确的结果，不只是一句 toast。

建议最小实现：

- W15 组件顶部增加一个状态区域，例如 `#w15_sync_status`。
- 成功后显示：
  - `已写入云端`
  - `成交 ID #xx`（如果后端返回）
  - `现金` / `持仓` / `更新时间` 中至少一个可用字段
- 失败后显示：
  - `写入失败`
  - 后端返回的具体原因

如果 `/api/sync` 当前只返回 `trade_id` 和 `ok`，可以先显示：

```text
已写入云端 · 成交 #37
```

不要为了这个任务改后端返回结构。

### 4. W15 modal 内联错误复用

已有 `#f_error`。要求：

- 本地校验失败：继续显示 `#f_error`。
- HTTP 403 / 后端拒绝：也显示 `#f_error`。
- 网络失败：显示“网络错误，成交未保存”。
- 成功后关闭 modal，并更新 W15 顶部状态区域。
