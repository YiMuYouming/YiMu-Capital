# 实时数据管线 v2.0 实施计划

**目标：** 用 PyTDX（TCP 通达信）+ 东方财富（HTTP）+ easyquotation（兜底）替代已停用的 iwencai 轮询，实现零被封风险的秒级实时数据管线。

**架构：** poll_live.py 三源混合 → dashboard_live.json → store.js merge() → widgets。复盘基线（Layer 1）保持 iwencai 体系不变，实时覆盖（Layer 2）换 PyTDX 体系，两个体系通过 SSOT 严格分离，各自管各自的数据域。

**技术栈：** Python 3（mootdx, requests, easyquotation），JavaScript（store.js 恢复实时管线），纯前端看板不变。

## SSOT 全量审计

### 核心原则

> **复盘用 iwencai，实时用 PyTDX，两者数据域不交叉。每个字段只有一个权威来源。**

### 关键冲突点及处理

#### 冲突 1：概念板块命名不一致

| 复盘笔记中的名称 | 东方财富可能的名称 | 处理方式 |
|-----------------|------------------|---------|
| 机器人 | 机器人概念 / 机器人 | 模糊匹配 + 手动映射表 |
| 光通信 | 光通信 / 光模块 | 同上 |
| 算力租赁 | 算力 / 东数西算 | 同上 |
| 航天/军工 | 航天航空 / 军工 | 同上 |
| PCB | PCB / 印制电路板 | 同上 |
| 半导体 | 半导体 / 半导体概念 | 同上 |
| 电力 | 电力行业 / 电力 | 同上 |
| 锂电 | 锂电池 / 锂电 | 同上 |

**方案：** poll_live.py 内置 `SECTOR_NAME_MAP` 字典，复盘笔记名称 → 东方财富 BK 代码。首次运行时自动尝试模糊匹配，匹配不到的手动补充。未匹配的板块在 live_sectors 中显示 "—"。

#### 冲突 2：涨幅含义不一致

- Layer 1 `lianban_pool[].涨幅`：昨日收盘涨幅（iwencai 计算，基点是前日收盘价）
- Layer 2 `live_quotes[code].涨幅`：盘中实时涨幅（PyTDX 计算，基点是今日开盘价/昨日收盘价）
- merge() 会用 Layer 2 覆盖 Layer 1，所以看板上显示的是**盘中实时涨幅**
- W04 通过 `getInitialBase()` 保留昨日收盘基线用于对比

**方案：** 不改 merge() 逻辑，涨幅 overlay 是正确行为。W04 已经通过 initialBase 区分昨日 vs 今日。

#### 冲突 3：涨停家数口径不一致

- `market.涨停家数`：来自复盘笔记（iwencai 或人工统计），是**昨日全市场**涨停数
- `live_sectors[板块].今日涨停数`：来自东方财富，是**今日盘中该板块**涨停数
- 两者是不同数据路径，不冲突。但 W10 展示板块涨停数时用的是 live_sectors，W04 展示全市场涨停数时用的是 market

**方案：** 保持分离。全市场级别用 Layer 1（复盘基线），板块级别用 Layer 2（实时）。

#### 冲突 4：iwencai 独占数据不可替代

以下数据只有 iwencai 能提供，PyTDX/东方财富都拿不到：
- 热榜排名（人气榜/热度榜）
- 龙虎榜（席位/买卖金额）
- 涨停收益 / 炸板收益（iwencai 算法）
- 晋级率（iwencai 算法：n板→n+1板比例）
- 连板梯队结构

**方案：** 这些保留在 iwencai 体系，通过 `poll_iwencai.py --review` 盘后按需查询。

## iTick WebSocket 切换预案

如果 PyTDX 长期不稳定（连接频繁断开、数据缺失），切换到 iTick WebSocket 只需：

1. `pip install itrade`
2. 在 poll_live.py 中新增 `fetch_quotes_itick()` 函数
3. 启动时加 `--source itick`

板块数据仍用东方财富（iTick 无板块），输出格式不变。切换成本约 20 行代码。
