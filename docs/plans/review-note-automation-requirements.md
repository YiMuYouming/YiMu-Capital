## Context

复盘笔记当前承担双重职责：**数据日志**（表1 35 格、表2 52 格、frontmatter 26 字段）和**策略日记**（节点说明、心得、预案、对抗）。每天收盘后，稳米把弈沐哥传来的数据逐一贴进笔记，费时 40-60 分钟。

live-dashboard Phase 0-3 重构完成后，T1/T2/T3 数据已全自动采集（quotes 5s、iwencai 2min、sentiment 30min 快照、auction 9:25 快照）。**数据管线全有，人不应再贴。**

核心原则：**复盘留给策略记录和回顾，数据获取留给 pipeline。笔记变成纯策略文档，数据由管线自动注入。**

### 关键设计决策：Frontmatter 数据不 5 秒更新

**Frontmatter 只需要收盘快照，不需要盘中实时数据。** 原因：

- live-dashboard 已经 5 秒刷新实时数据，盘中共看足够了
- 笔记的 frontmatter 是**收盘后一次性填入的最终值**，代表"这个交易日定格时的状态"
- 盘中填 frontmatter 既重复（dashboard 已有）又低效（多次编辑同一字段）
- 30min 快照和收盘快照已经保留了全天的时序数据，复盘时可以回溯任意时刻

同理，表1/表2 的各节点数据也在收盘后**一次性从 30min 快照中提取**填入，不需要盘中逐节点手工填。

## 三、当前痛点和缺口

### 痛点 1：sentiment_auto.json 快照不完整

当前 30min 快照缺少关键字段：上证指数/涨幅、涨跌比、量能、连板收益、炸板收益。导致表1 大部分列无法自动填。

**修复**：扩增 `sentiment_snapshot.py`，快照时同步抓取 live_index 和 live_breadth 数据。

### 痛点 2：没有"收盘数据包"

复盘需要的是**收盘时刻的最终值**，但 bridge CACHE 只存最新值。30min 快照覆盖了日内每个时间节点，但 frontmatter 需要一个收盘时的完整数据快照。

**修复**：新增 `scripts/snapshot_close.py`，收盘时（15:02）跑一次，输出 `data/close_snapshot_{date}.json`。

### 痛点 3：style_detect.py 外部依赖 — ✅ 已修复

`style_detect.py` 已复制到 `live-dashboard/scripts/style_detect.py`（918 行），原始文件保留在 WorkBuddy（稳米也在用）。gen_dashboard_data.py 路径已同步改为 `ROOT_DIR / "scripts" / "style_detect.py"`。零外部依赖。

### 痛点 4：Portal convert_review.py 强依赖 Markdown 表格格式

如果修改笔记格式，convert_review.py 的表格解析可能失效。

**策略**：第一阶段不改笔记格式，只自动填值；第二阶段改格式时同步更新 convert_review.py。

#### Step 1.3：新建 fill_review_note.py（核心，3-4h）

**位置**：`scripts/fill_review_note.py`

**功能**：
1. 输入：笔记路径 或 日期（默认今天）
2. 读取所有磁盘数据源（独立进程，不读 bridge CACHE）：
   - `close_snapshot_{date}.json`（收盘数据包，frontmatter 主力源）
   - `sentiment_auto.json`（30min 快照，表1/表2 按节点取最近值）
   - `auction_snapshot.json`（竞价数据）
   - `pools.json`（自选池 SSOT）
   - `pnl.db`（P&L 计算）
   - `dashboard_data.json`（baseline，含 style 检测，作为兜底）
3. 如果笔记已存在 → 只填充空字段（不覆盖人写内容）
4. 如果笔记是模板 → 全部填充
5. 输出到原路径，人打开后只写红色字段

**填充逻辑**：

```
笔记路径 → 检测现有内容 → 逐节填充：

Frontmatter:
  读 close_snapshot → 填全部管线字段（一次性）
  保留人填的: date, weekday, 盘后持仓

表1 大盘全景:
  读 sentiment_auto.json 当天快照
  每个节点找时间戳最近的快照
  填: 情绪/上证(%)/涨跌停/量能/涨跌比
  竞价节点额外读 auction_snapshot.json

表2 情绪高标:
  同上，读 sentiment_auto.json
  填: 涨停收益/连板收益/炸板收益/封板率/炸板率/晋级率/赚钱效应/最高板/次高板/竞价强势家数
  自动判定: 每格是否满足门槛（>2%✅ / ❌）

涨停结构:
  从 iwencai 连板股列表按板块归类
```

## 六、盘中 AI 互动详解

改造后，盘中 AI 互动有三个层次：

### 层次 1：自动运行（零操作）

W20 AI盯盘 每 15 分钟自动触发一次 DeepSeek 研判。输出：
- `[TEXT]` 3-5 句中文研判（结论优先）
- `[SIGNALS]` 结构化信号（BUY/WATCH/RISK/INFO | 标的 | 多/空/— | 高/中/低）

每个信号经过规则交叉验证（`_verify_signals()`），打上 ✅/⚠️ 标记后才展示。W10 板块热力卡片的 🤖 槽位自动匹配当前板块，展示最新 AI 研判。

**W1 时段（9:30-10:00）特别增强**：AI 自动收到 W1 专属提示，优先输出龙头状态、板块合力、W1 候选标的、竞价三件套四项评估。

### 层次 2：手动触发（一鍵）

弈沐哥在任何时候想听 AI 的意见，在 W20 点"刷新"按钮 → 立即触发一次研判，DeepSeek 返回当前全盘快照的分析。适合：
- 竞价结束想知道方向判断
- 午盘开盘前想知道下午策略
- 某个板块突然异动想快速理解

### 层次 3：对话式分析（收盘后）

洋米（Claude Code）在收盘后执行红方对抗，这是深度分析。读完整复盘笔记 + 独立跑问财数据 + 五维清单交叉验证 + 三回合辩论。这层不要求实时，但要求深度。

```
9:30  ─ W1 开始 ──── W20 自动触发 (W1增强提示)
```

1. **iwencai API 配额**：新增查询会增加 API 调用。连板收益/炸板收益查询复用已有轮询周期（2min），不额外增加频率。

3. **数据缺失降级**：如果某天 iwencai 挂了或 snapshot 缺失，fill 脚本标记 `⚠️ 管线数据缺失`，不填入错误值。

4. **和现有 gen_dashboard_data.py 的关系**：gen 脚本在重构后角色已变更为数据校验者（T1/T2 字段不再首次写入）。fill 脚本把管线数据写入笔记后，gen 读笔记做一致性校验。数据流向：
   ```
   Pipeline → bridge CACHE → snapshot_close.py → close_snapshot.json (磁盘)
                                │
   fill_review_note.py 读磁盘 ←─┘
        │
        ▼
   笔记.md (管线数据已填入，人只写定性)
        │
        ▼
   gen_dashboard_data.py (校验者：读管线数据，验证一致性)
        │
        ▼
   dashboard_data.json → 看板 Layer 1 基线
   ```

5. **历史笔记兼容**：fill 脚本只处理今天及以后的笔记，历史笔记不动。

6. **Frontmatter 非实时更新**：frontmatter 数据是收盘后的最终快照值，不是 5 秒更新。盘中实时数据通过 live-dashboard 看，不在笔记里追。
