# live-dashboard 数据自动化分层方案

> 调研日期：2026-05-18 | 依据：YM-data-pipeline 15 类型全量实测 + 仪表盘 72 字段逐项分级
> 核心原则：**能实时获取的永不靠人填，能计算的永不靠文件传**

---

## 零、数据获取优先级（宪法级）

```
T1 实时自动获取（秒级）
  ↓ 不可用时降级
T2 阶段性自动获取（分钟/小时/日级）
  ↓ 不可用时降级
T3 实时计算可得（从 T1+T2 推导）
  ↓ 不可用时降级
T4 复盘笔记/人工录入（最后手段）
```

**红线**：T1/T2 能覆盖的数据字段，不允许复盘笔记作为主源。复盘笔记的 frontmatter 变成"人工校验覆盖"而非"首次写入"。

## 一、YM-data-pipeline 实测结果

17 个数据类型测试（2026-05-18 11:43 盘中），16 个通过：

### L1 基础行情

| 类型 | 延迟 | 鉴权 | 实时 | 关键字段 |
|------|------|------|------|---------|
| `iwencai` | 1.4-2.4s | API KEY | 配额制(5000/15min) | 任意 A 股字段 |
| `ths_hot` | 0.43s | 无 | 分钟级 | 83只热点+题材归因+涨停统计 |
| `tencent` | 0.38s | 无 | 无限制 | PE/PB/市值/换手率（需传 codes） |

### L2 技术分析 (PyTDX)

| 类型 | 延迟 | 鉴权 | 实时 | 关键字段 |
|------|------|------|------|---------|
| `quotes` | 1.59s | 无(TCP) | 5s | 最新价/涨幅/量比/换手/MA5/10/20/60m |
| `index` | 1.01s | 无(TCP) | 5s | 三指数+涨跌家数+成交额+振幅 |
| `breadth` | 4.18s | 无(TCP) | 30s | 全市场十档涨跌分布(5000+只) |
| `sector_index` | ~0.5s | 无(TCP) | 30s | 板块涨跌幅/MA5/20/方向/成交额趋势 |
| `kline` | ~0.4s | 无(TCP) | 按需 | 日/60m/15m/5m K线+均线 |
| `kline_15m` | ~0.5s | 无(TCP) | 5min | 三指数15分钟量价(同比昨日) |

### L3 资金流向

| 类型 | 延迟 | 鉴权 | 实时 | 关键字段 |
|------|------|------|------|---------|
| `northbound` | 0.88s | 无 | 分钟级 | 262分钟点/沪股通+深股通累计 |
| `dragon_tiger` | 0.61s | Referer | 每日盘后 | 112条龙虎榜/净买额 |
| `sector_inflow` | 3.03s | 无 | 分钟级 | 50行业净流入/领涨股/涨跌家数 |

### L4 研报/公告/新闻

| 类型 | 延迟 | 鉴权 | 实时 | 关键字段 |
|------|------|------|------|---------|
| `news` | 0.29s | 无 | 分钟级 | 20条财联社电报 |
| `research` | 3.43s | Referer | 按需 | 东财研报(需传 code) |
| `filings` | 0.44s | 无 | 按需 | 巨潮公告(需传 code) |

### 实测发现的设计问题

1. **`quotes`/`tencent`/`research`/`filings` 需传 codes 参数**，无默认值。解决方案：从 pools.json 读取自选池代码列表作为默认输入。
2. **`breadth` 延迟 4.18s**，不适合 5s 轮询。解决方案：30s 定时刷新 + 内存缓存。
3. **`dragon_tiger` 盘中返回空**，仅盘后有效。符合预期。
4. **所有 14/15 类型无需鉴权**，仅 `iwencai` 需要 API KEY。

### T3 — 实时计算可得（~12 字段）

从 T1+T2 纯逻辑推导，不需要额外取数。

| # | 字段 | 计算公式 | 依赖 |
|---|------|---------|------|
| 32 | 情绪值（实时版） | `上涨/(上涨+下跌)*100` | T1 涨跌家数 |
| 33 | 情绪区间 | <20冰点 <40低迷 <60主升 <80强势 ≥80高潮 | T3 情绪值 |
| 34 | 涨跌比 | `上涨/下跌` | T1 涨跌家数 |
| 35 | 赚钱效应（T3版） | 涨停收益>3%+连板收益>0+风险值<0.5→"好" | T2 涨停/连板/风险值 |
| 36 | 浮盈/浮亏（每只持仓） | `(现价-成本)*数量` | T1 现价 + T4 成本 |
| 37 | 浮动盈亏率 | `浮盈/(成本*数量)*100` | 同上 |
| 38 | 持仓市值 | `现价*数量` | T1 现价 + T4 数量 |
| 39 | 总仓位占比 | `持仓市值/总资产*100` | T3 持仓市值 + T4 总资产 |
| 40 | 竞价信号灯（涨跌/强势/高标/综合） | `_auto_lights()` 判定表 | T2 竞价数据 |
| 41 | 日累计回撤 | `max(1-NAV/峰值_NAV)` | T2 intraday_snapshots |
| 42 | 连亏天数 | 连续 `pnl_pct < 0` 日计数 | T2 daily_summary |
| 43 | 规则引擎（总仓位上限/熔断/连亏/周五/无强支线） | `compute_style_execution()` | T4 熔断声明 + T2 晋级率 |

### T4 — 必须人工/复盘笔记（~12 字段）

无法自动化——需要人的判断、决策、或当日盘中手工填写。

| # | 字段 | 为何非人工不可 | 优化方向 |
|---|------|--------------|---------|
| 44 | 风格检测（总分/风格/四维度） | 多日数据+规则引擎+人工判定 | `style_detect.py` 已半自动，每日盘前跑一次 |
| 45 | 连板占比/趋势占比/总仓位上限 | trading-core 插值表 | 已由 style_detect 规则引擎计算 |
| 46 | 自选池构成（连板+趋势+锚定） | 红方对抗后的策略决策 | pools.json SSOT，稳米盘前更新 |
| 47 | 板块状态（主线/强支线/退潮） | 方向定性判断 | 复盘笔记附录A，稳米盘前更新 |
| 48 | 持仓成本/数量 | 交易记录 | 可从 SQLite trade_records 自动汇总 |
| 49 | 总资产/可用资金 | 账户信息 | W16 手工录入，或从券商API（未来） |
| 50 | 当日盈亏声明 | 可选——T3 已可计算 | 人工校验 vs T3 计算值 |
| 51 | 熔断触发声明 | 需要人确认"真的熔断了" | T3 可预警("日内浮亏≥3%")，人确认 |
| 52 | W1/W2 状态（开放/关闭/降半仓） | 策略决策 | 可由 T3 情绪区间+晋级率自动建议，人确认 |
| 53 | 情绪节点 5 节点矩阵 | 稳米盘中填写 | **最大自动化机会**——30min自动快照可替代手工 |
| 54 | 今日操作记录 | 交易执行 | W15/W17 手工录入，可联动 SQLite |
| 55 | 预警/不碰列表 | 策略排除 | 附录A pools.json `excluded` 字段 |

## 四、数据源优先级矩阵（修改后的 store.js merge 逻辑）

```
数据字段的读取优先级（从高到低）：

情绪值:
  T3 实时计算（上涨/(上涨+下跌)*100）      ← 主源, 每 5s
  T2 iwencai 查询（style_detect dim4）     ← 校验, 每 2min
  T4 复盘笔记 frontmatter                    ← 仅收盘后覆盖

涨停家数/跌停家数:
  T1 PyTDX breadth 实时扫描                 ← 主源, 每 30s
  T2 iwencai 查询                           ← 校验
  T4 复盘笔记                                ← 盘后校验

封板率/炸板率/晋级率/最高板/连板收益/风险值:
  T2 iwencai 查询（盘中每2min）              ← 主源
  T4 复盘笔记                                ← 盘后补充

竞价数据:
  T2 iwencai 9:25 快照                      ← 主源
  T4 复盘笔记 frontmatter                    ← 不在 9:25-10:00 时段时 fallback

自选池/板块状态/持仓成本:
  T4 人工决策                                ← 唯一的源（策略决策不可自动化）

实时行情/指数/板块/15min量价:
  T1 PyTDX                                   ← 唯一的源（不需要 fallback 到复盘笔记）
```

## 五、对重构计划的影响

1. **计划中"SSOT 存储 = baseline.json + pools.json"需要扩展**：增加 `live_cache`（内存）和 `sentiment_auto.json`（30min 自动快照）
2. **gen_dashboard_data.py 的角色从"数据生产者"变为"数据校验者"**：T1/T2 已覆盖的字段，gen 脚本只做校验不首次写入
3. **复盘笔记 frontmatter 大幅瘦身**：T1/T2 覆盖的字段可以从 frontmatter 中移除（或标记为 `auto` 不手工填写），只保留 T4 字段
4. **poll_live.py 拆分时优先集成 pipeline 的标准化接口**：用 `fetch()` 替代内联 PyTDX 调用，统一字段格式
