## 1. 架构总览

```
数据采集层:
  poll_live.py (每300s) → PyTDX → 算P&L → data/pnl.db (SQLite)
  历史回填: backfill_intraday.py → PyTDX 5min K线 → pnl.db

API 层:
  bridge.py GET /api/pnl?range=today|week|month|quarter|year&index=sh|sz|cy
           GET /api/pnl?range=all  (日频汇总)
           GET /api/pnl/summary

前端层:
  store.js → merged 数据 (实时报价+持仓) → W22 render()
  pnl-curve.js → fetch /api/pnl → Canvas 折线图 + KPI 卡片 + 损益明细抽屉
```

### 数据库 (data/pnl.db)

| intraday_snapshots | 日内 P&L 快照 (672条) | 5分钟 |

## 3. 已知问题 🔴

### 3.1 KPI 卡片与损益明细数字不一致

**症状**: 切换到「本周」，KPI 卡片显示本周收益 X%，打开损益明细抽屉，本周行显示 Y%（不同值）。

**根因**: KPI 和抽屉用了两套不同的数据源和算法：
- KPI 从 chartData（5分钟 K 线）取最后一个数据点
- 抽屉从 daily_summary（日频 TWR 连乘）取时段累计

**目标**: KPI 和抽屉共享同一数据源，数字完全一致。

**已做修复方向**: 抽屉改为读取 `_periodCache`（各时段缓存的 chart 数据），与 KPI 同源。但预加载逻辑未完整实现，导致抽屉首次打开时数据为空。

### 3.2 仓位子图首次加载空白

**症状**: 刷新页面后勾选「显示仓位」，子图空白；切到其他时段再切回来才出现。

**根因**: 仓位数据需要从 `/api/pnl?range=all` 预加载，预加载是异步的。勾选时缓存未就绪。

**目标**: 首屏即预加载，勾选即时显示；预加载完成自动绘制。

### 3.3 损益明细"累计"行数据错误

**症状**: 累计行显示的收益不反映真实 TWR 累计。

**根因**: 累计行取了最后一条日频记录的值（单日），而非从起始到今天的累计。

**目标**: 累计 = 各时段收益 TWR 连乘，或从 daily_summary 所有记录计算。

### 3.4 页面首次加载时 W22 不渲染图表

**症状**: 强刷页面后曲线空白，需要切换标签或等待 30s 才出现。

**根因**: render() 重建 DOM 后异步 fetch 图表数据，但回调执行时可能 DOM 元素未就绪，或 `_state` 初始化与 `_bindEvents` 时序问题。

---

## 4. 优化方向 🟡

| 方向 | 说明 |
|------|------|
| **统一数据源** | KPI、图表、抽屉全部走 `_periodCache`，不再混用 chartData / daily_summary |
| **预加载策略** | 首屏一次性拉取 5 个时段的图表数据，存入 `_periodCache`，KPI 和抽屉直接从缓存读 |
| **减少 DOM 重建** | 当前 render() 每次用 innerHTML 重建整个组件 → 改为只更新变化的文本节点 |
| **抽屉即时渲染** | 抽屉打开时无需额外 fetch，直接从 `_periodCache` 渲染 |
| **错误边界** | 每个 async fetch 加 fallback 空状态，避免白屏 |
