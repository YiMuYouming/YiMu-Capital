## 1. 产品概述

### 1.1 定位

账户收益曲线组件是弈沐资本数据看板的补充组件（W22），提供**盘中实时持仓浮动盈亏曲线**与**历史累计收益分析**。同时支持盘后数据导出到门户网站（GitHub Pages）公开展示。

### 1.2 核心价值

| 痛点 | 解决方案 |
|------|---------|
| 当前看板只有实时盈亏数字，无历史曲线 | Canvas 折线图展示时段内盈/亏走势 |
| 无法比较账户 vs 大盘表现 | 上证/深证/创业板可选对比曲线 |
| 追加资金后收益率失真 | TWR 时间加权收益率，反映真实交易能力 |
| 收市后数据无法公开查看 | 数据同步到门户站，GitHub Pages 展示 |

## 2. 组件规格

### 2.1 组件 ID

- **看板组件 ID**：W22
- **类型**：`data`
- **层级**：`tick`（5s 刷新实时数据，1min 快照记录）

### 2.2 默认尺寸

- **w**: 12（全宽），**h**: 10

### 2.3 数据依赖

| 数据路径 | 来源 | 用途 |
|---------|------|------|
| `live_quotes` | poll_live.py → dashboard_live.json | 个股实时价→算持仓市值 |
| `positions` | W15 记流水 → dashboard_data.json | 持仓代码/成本/数量 |
| `pnl.总资产` | W16 报总资产 → dashboard_data.json | P&L% 计算分母 |
| `pnl.累计入金` | W16 报入金 → dashboard_data.json | 累计收益额 = 当前资产 − 累计入金 |
| `pnl_history` (store.js 新增第五层) | poll_live.py → pnl_history.json | 历史快照/日频数据 |

### 3.2 KPI 卡片（5卡单行）

| 位置 | 卡片 | 数据源 | 说明 |
|------|------|--------|------|
| 1 | 当前资产 | W16 总资产 | `manualData['总资产']` 或实时计算 |
| 2 | 持仓盈亏 | positions × live_quotes | 主动持仓的浮动盈亏 |
| 3 | 仓位 | 持仓市值 / 总资产 | 百分比 + 持仓只数 |
| 4 | [动态] N日收益 | periodData[n].pnl | 跟随时间选择变化 |
| 5 | [动态] N日回撤 | periodData[n].dd | 跟随时间选择变化 |

**动态联动**：点击时间选择（今日/本周/本月…）→ 第4、5卡内容自动更新。

### 3.3 时间选择

| 选项 | 图表粒度 | 数据范围 | 数据源 |
|------|---------|---------|--------|
| 今日 | 5min 线 | 9:30-15:00 日内快照 | `pnl_history.json > intraday` |
| 本周 | 日线 | 本周一到今天 | `pnl_history.json > daily` |
| 本月 | 日线 | 本月1号到今天 | `pnl_history.json > daily` |
| 近三月 | 日线 | 近90天 | `pnl_history.json > daily` |
| 近一年 | 周线 | 近365天 | `pnl_history.json > weekly` |
| 自定义 | 自适应 | 用户选择起止日 | 智能降采样 |

### 3.4 指数对比选择

切换对比指数（上证/深证/创业板），图表中蓝虚线自动切换为对应的基准指数曲线。默认上证。

### 3.5 自动回撤高亮

每个时间周期自动计算该时段内的最大回撤（峰值→谷值），在图表上标注：
- 🟧 橙色区域背景浅橙底色
- 橙色粗线标出从峰到谷的回撤路径
- 峰/谷位置标圆点 + 时间标注
- 线段下方标注回撤百分比

### 3.6 损益明细抽屉

点击「📊 损益明细 ▼」展开/收起详细损益表：

| 列 | 内容 | 格式 |
|----|------|------|
| 周期 | 今日/本周/本月/近三月/近一年/累计 | 文字 |
| 账户收益 | TWR 收益率 | `+x.xx%` 红色/绿色 |
| 基准收益 | 对应指数收益率 | `+x.xx%` |
| 超额 α | 超越基准 | `+x.xx%` |
| 最大回撤 | 周期内最大回撤 | `-x.xx%` |

## 4. 数据架构

### 4.1 数据流总览

```
W15 记流水 ──→ bridge POST /api/sync ──→ dashboard_data.json (持仓+成本)
W16 报总资产 ──→ bridge POST /api/sync ──→ dashboard_data.json (pnl.总资产+pnl.累计入金)
                                                  │
                                                  ↓ (poll_live.py 循环体)
poll_live.py (每60s):
 ① 读 dashboard_data.json → positions(代码/成本/数量) + pnl.总资产 + pnl.累计入金
 ② 读 PyTDX → 个股实时价 + 上证/深证/创业板 涨幅
 ③ 算 P&L = Σ[(当前价-成本)×数量] / 总资产
 ④ 算 TWR NAV = 上日NAV × (1 + 今日累计P&L%)
 ⑤ 追加快照到 pnl_history.json
                                                  │
                                                  ↓ (前端)
store.js 四层合并 → W22 组件
 Layer1: dashboard_data.json (基线)
 Layer2: dashboard_live.json (实时报价)
 Layer3: manualData (W16手工)
 Layer4: pnl_history.json (历史快照, fetch定时拉)
                                                  │
                                          盘后手动推 portal
```

### 4.2 总资产同步机制（关键链路）

当前 W16 的总资产存在浏览器 localStorage 中，poll_live.py 无法读取。

**方案**：扩展 bridge.py `/api/sync`，W16 报数面板增加同步逻辑：

```
W16 报总资产 → DataStore.manualData.set('总资产')
              → 调用 bridgeSyncPnl({总资产, 累计入金})
              → bridge POST /api/sync
              → body: { positions, 今日操作, pnl: {总资产, 累计入金} }
              → dashboard_data.json 增加 pnl 域
```

`dashboard_data.json` 新增字段：
```json
{
  "pnl": {
    "总资产": 1012000,
    "累计入金": 2000000,
    "last_nav": 1.1245,
    "nav_date": "2026-05-14"
  }
}
```

这样 poll_live.py 通过读 `dashboard_data.json > pnl.总资产` 即可获取基线。桥接服务必须运行（`python3 scripts/bridge.py 8088`）。

### 4.3 pnl_history.json 加载机制

store.js 新增第四层数据层：

```js
// store.js 新增
adapter.fetchPNL = function() {
  return fetch('data/pnl_history.json?t=' + Date.now())
    .then(function(r) { return r.ok ? r.json() : null; })
    .catch(function() { return null; });
};
```

加载时机：
- 组件 mount 时拉一次
- 每 60s 自动轮询刷新
- 不阻塞其他三层加载（独立 Promise）

### 4.5 TWR 计算逻辑

时间加权收益率（TWR）分段计算：

```
第1段: 初始100万 → 101万      → +1.00%
追加 100 万（101万资产+100万入金 = 201万）
第2段: 201万 → 206万          → +2.49%
TWR = (1+0.01) × (1+0.0249) - 1 = +3.49%

累计净值 nav = 1 + TWR
当前净值 1.0349
累计收益额 = 当前资产 - 累计入金 = 206 - 200 = +6万
```

### 4.6 P&L 采集机制

**采集位置**：扩展 `poll_live.py` 的 `--watch` 循环体（不新建脚本）。

```
poll_live.py watch 循环（每5s-60s）：
① 读 dashboard_data.json → positions (代码/成本/数量) + pnl.总资产 + pnl.累计入金
② 调用 get_stock_codes() 已获取代码列表（已有）
③ 调用 fetch_quotes_pytdx() 获取实时价（已有）
④ 新增：读取 fetch_index_pytdx() 获取三大指数涨幅（已有）
⑤ 新增：P&L 计算：
   持仓市值 = Σ(数量 × 最新价)
   持仓成本 = Σ(数量 × 成本价)
   浮动盈亏 = 持仓市值 - 持仓成本
   浮动收益率 = 浮动盈亏 / pnl.总资产 × 100
   仓位% = 持仓市值 / pnl.总资产 × 100
⑥ 新增：每60s追加一条快照到 data/pnl_history.json
   {t: "HH:MM", nav: TWR_NAV, pnl_pct: 浮动收益率, 
    sh_pct: 上证%, sz_pct: 深证%, cy_pct: 创业板%, 
    pos_pct: 仓位%, mv: 持仓市值}
```

**NAV 初始化**：
- 首次运行：用户第一次报总资产时，设置 `nav = 1.0`（本日基线）
- 非首日：从上日 daily 记录的 `nav` 接过
- 盘中 poll_live 重启：从 `pnl_history.json > meta.last_twr_nav` 接过

**日终结算**（收盘后）：
- 取最后一条 intraday 数据作为 daily 记录
- 如果当天有追加资金，poll_live.py 设 deposit 金额（通过 dashboard_data.json > pnl.累计入金变化计算）
- daily.deposit > 0 → TWR 分段

**非交易日处理**：
- poll_live.py 不运行时图表回到日频数据
- 组件检测是否有今日 intraday 数据，无则自动退到 daily

## 6. 图表渲染技术选型

**选择：原生 Canvas API**（零依赖）

理由：
- 看板维持零构建原则，不引入外部库
- 折线图 + 区域填充 + 标注，Canvas 原生 API 完全够用
- 不依赖 CDN，file:// 协议可用
- portal 站可复用同一份 Canvas 渲染函数

## 7. 已知限制 & 未来扩展

| 限制 | 说明 | 未来方案 |
|------|------|---------|
| 盘中 P&L 基于持仓浮动盈亏，不含未报单 | 未成交订单不计入 | 接入券商 API 后实时拉真实总资产 |
| TWR 需要准确记录追加资金时间点 | W16 手工报可能遗漏 | 自动化入金流水（银行流水对接）|
| intraday 快照频率受 poll_live.py 运行状态影响 | poll_live 停止则无数据 | 独立常驻服务 + systemd 保活 |
| portal 同步为手动 | 收盘后人工触发 | 自动化 CI/CD 推送 |
| **总资产需通过 bridge 同步** | W16 填总资产后需 bridge.py 运行才能落地到 JSON | 已设计扩展 /api/sync，bridge 必须常开 |
| **初始 NAV 需要种子数据** | 首次运行无历史 daily 记录 | 用户首次报总资产时自动 nav=1.0 |
| **非交易日无 intraday** | 周末/节假日 poll_live 不运行 | 组件自动退化到 daily 数据显示 |
